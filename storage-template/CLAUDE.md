# OPC 资料库协作规则与 LLM Wiki 规范

本文件定义“AI+跨境电商 OPC 内容量化增长引擎”业务资料库的目录边界、命名规范、内容合规和 AI 协作方式。Claude、Codex 及所有自动化 Agent 必须共同遵守，不得自行恢复旧目录或创建平行存储链路。

## 权威来源与可移植性

- 当前文件所在目录就是资料库根目录。
- 程序通过 `OPC_VAULT_ROOT` 挂载资料库；业务文件不得写入某台电脑的绝对路径。
- GitHub 仓库只保存空目录模板和本文件，不保存真实产品资料、账号、脚本、图片、视频、音频、发布数据或密钥。
- 本节“正式 OPC 目录结构”是视频工作流的唯一权威路径。
- 初始化程序只补齐缺失目录和缺失模板文件，不覆盖已有业务文件。
- 目录结构、命名规则或本文件发生变化时，必须同步更新 8888 全局路径、对应 Agent、空目录模板和测试。

## 资料库定位

资料库由两个互相协作的板块组成：

1. **产品 Wiki**：保存产品事实、产品图片、内容策略、来源和可复用知识。
2. **视频内容工厂**：保存来源素材、参考脚本、正式脚本、模型适配、AI 片段、合成工作区、成品和发布文案。

两者共享产品信息、文件命名、市场语言和合规规则。任何 Agent 都不得各自维护互相冲突的产品事实。

## 文件与产品命名规范

### 产品文件

- 产品信息：`{项目代码}-{产品名}-产品信息.md`。
- 产品底图：`{项目代码}-{产品名}.扩展名` 或现有产品统一文件名。
- 产品信息不按国家重复建档；市场、国家和语言写在文件内容中。
- 产品事实以 `wiki/产品/产品信息/` 为准，产品参考图以 `wiki/产品/产品底图/` 为准。
- 产品简称在所有 Agent 中必须一致，不得为同一产品创建多个近似名称。

### 国家与市场

使用稳定的国家或地区缩写，例如 `US`、`UK`、`IE`、`ES`、`IT`、`DE`、`MY`、`PH`、`VN`。无法识别时可用 `UNK`，确认后应修正。

- 国家、目标语言、来源账号和视频 ID 优先写入文件名或 Frontmatter。
- 不为国家、来源类型或脚本类型额外创建平行顶层目录。
- 多站点共用一个产品事实源，市场差异写入脚本和发布文案。

### Prompt 目录

- 保存 Prompt 的目录使用“提示词”后缀。
- 保存实际产出图片的目录不使用“提示词”后缀。
- 多站点共用素材时，应明确通用语言；单一市场素材使用目标市场语言。

### 纯 AI 视频命名

#### 来源素材

`纯AI视频/01来源素材/<产品名>/`

推荐格式：

```text
{用户名}-{视频ID}-{视频标题}.mp4
{用户名}-{视频ID}-{视频标题}.json
```

MP4 与 JSON 必须使用相同主文件名。JSON 保存来源 URL、视频 ID、账号、标题和采集日期。

#### 参考脚本

`纯AI视频/02参考脚本/<产品名>/`

推荐格式：

```text
{国家}-{用户名}-{视频ID}-{标题}.md
```

参考脚本只表示来源视频的解析结果，不等同于已批准的正式产品脚本。

#### 正式产品脚本

`纯AI视频/03产品脚本/<产品名>/`

统一以文件名前缀区分来源，不建立“爆款复刻”“产品改写”或“AI 原创”子目录：

```text
复刻-{产品名}-{国家}-{来源标识}-{来源ID}.md
改写-{产品名}-{国家}-{来源标识}-{来源ID}.md
原创-{产品名}-{国家}-{任务标识}.md
裂变-{产品名}-{国家}-{来源标识}-{来源ID}.md
裂变-{产品名}-{国家}-{来源标识}-{来源ID}_{NNN}.md
```

- 同一来源的主文件名必须贯穿适配、片段、合成和成品。
- 同名裂变使用三位递增编号，如 `_002`、`_003`。
- 一个来源只保留一个基础复刻版本；新的创意变化进入裂变版本。
- 程序识别依赖统一命名，任何 Agent 不得私自改变词序。

#### 适配脚本与 AI 片段

```text
纯AI视频/04适配脚本/<模型>/<产品名>/<主文件名>.md
纯AI视频/05AI片段/<模型>/<产品名>/<主文件名或任务名>/
```

模型目录只使用既定名称 `grok`、`omni`、`veo`。源脚本、适配脚本和片段必须能通过主文件名互相追溯。

### AI 实拍混剪命名

```text
AI实拍混剪/01参考视频/<产品名>/
AI实拍混剪/02解析脚本/<产品名>/
AI实拍混剪/03复刻裂变脚本/<类型>/<产品名>/
AI实拍混剪/04适配脚本/<模型>/<类型>/<产品名>/
AI实拍混剪/05AI片段/<模型>/<类型>/<产品名>/
AI实拍混剪/06音频文件/<产品名>/
AI实拍混剪/07实拍素材/<产品名>/
AI实拍混剪/08混剪工作区/<产品名>/<任务名>/
```

- `<类型>` 只允许 `混剪-钩子` 或 `混剪-CTA`。
- 钩子与 CTA 的来源、解析、裂变、适配和片段必须保持同一主文件名。
- 实拍素材按产品组织，可在产品内部按“产品外观、使用展示、产品细节”等业务类别整理。
- 工作区属于任务编排，不得作为永久素材库。

### 成品和发布文案

```text
视频/成品视频/<产品名>/<成品文件名>.mp4
视频/成品视频/视频标题库/<产品名>.md
```

- 成品直接进入产品目录，不再按视频类型增加一层目录。
- 视频类型、国家、语言、账号或批次写进文件名和发布记录。
- 标题库按产品建一个 Markdown，可按国家或语言分章节。
- 每条发布文案保持“标题或正文 + 5 个标签”的统一格式。

## 页面规范

### 通用 YAML Frontmatter

Markdown 页面建议包含：

```yaml
---
title: ""
created: YYYY-MM-DD
updated: YYYY-MM-DD
tags: []
aliases: []
sources: []
---
```

### 页面类型

1. 实体页面：人物、组织、地点、平台和品牌。
2. 概念页面：方法论、术语、合规概念。
3. 来源摘要：对原始资料的结构化提取。
4. 合成页面：跨来源的分析、对比和结论。
5. 产品信息：电商产品事实。
6. 参考脚本：来源视频的结构化解析。
7. 产品脚本：复刻、改写、原创和裂变版本。
8. 适配脚本：面向具体视频模型的提示词和任务表。
9. 发布文案：标题、正文和标签。
10. 错题与规则：错误案例、修正措施和复用规则。

### 产品脚本 Frontmatter

```yaml
---
type: script-reproduction | script-rewrite | script-original | script-fission
project: 产品简称
project-code: XXX
market: 国家或地区缩写
language: 目标语言
source-script: "[[wiki/视频/纯AI视频/02参考脚本/产品名/来源文件.md]]"
script-id: 与主文件名一致
status: draft | approved | ready | published
publish-status: unpublished | scheduled | published
compliance-status: unchecked | passed | failed
methodology:
  - wiki/concepts/方法页面
knowledge-sources:
  - wiki/视频/共享知识库/脚本错题本/产品名
created: YYYY-MM-DD
updated: YYYY-MM-DD
---
```

原创脚本没有来源文件时，`source-script` 可以为空，但必须记录产品事实来源和创作任务标识。

### 适配脚本 Frontmatter

```yaml
---
type: model-adaptation
project: 产品简称
project-code: XXX
source-script: "[[wiki/视频/纯AI视频/03产品脚本/产品名/源文件.md]]"
model: grok | omni | veo
aspect-ratio: "9:16"
status: draft | ready | completed
compliance-checked: false
created: YYYY-MM-DD
updated: YYYY-MM-DD
---
```

### 错题本 Frontmatter

```yaml
---
type: project-library
library: mistakes | hooks | compliance
project: 产品简称
project-code: XXX
updated: YYYY-MM-DD
tags: [project-library]
---
```

### 链接约定

- 内部链接使用 `[[page-name]]` 或 `[[folder/page-name]]`。
- Wiki-link 使用相对路径，不加根目录开头的 `/`。
- 产品图片使用 `![[wiki/产品/产品底图/图片名.png]]`。
- 外部链接使用标准 Markdown：`[text](url)`。
- 标签使用小写英文，品牌名和专有名词除外。
- 链接目标移动后，必须同步更新引用，不得保留指向旧目录的链接。

## 产品信息文件格式

路径：

```text
wiki/产品/产品信息/{项目代码}-{产品名}-产品信息.md
```

建议包含以下板块：

1. 标题与市场概要。
2. 基本信息：产品、品牌、公司、项目代码、平台、英文名、类目。
3. 规格参数。
4. 核心功能。
5. TOP 3 卖点。
6. 适用场景。
7. 目标人群与痛点矩阵。
8. 市场定位与文化敏感点。
9. 双市场或多市场目标。
10. 成功标准。
11. 范围：做什么、不做什么。
12. 关键约束和合规红线。
13. AI 最容易犯的错误。
14. 关联页面。
15. 参考来源。

### 产品事实规则

- 用户提供并确认的产品事实优先于 AI 推断。
- 未确认的信息必须标注为推断，不得写成事实。
- 功效、成分、认证、价格、促销、运输和保修不得凭空补齐。
- 产品信息更新后，检查所有相关脚本、适配、发布文案是否需要同步。
- 产品底图不得由 Agent 擅自替换。

## 主图与详情图规范

| 类型 | 推荐比例 | 推荐尺寸 | 用途 |
|------|:--------:|:--------:|------|
| 产品主图 | 1:1 | 1000×1000 | 商品列表和主视觉 |
| 产品详情图 | 9:16 | 移动端适配 | 卖点、场景和说明 |
| 视频画面 | 9:16 | 1080×1920 | TikTok/Reels/Shorts |

- Prompt 必须明确目标语言、市场和画面用途。
- 不得在 Prompt 中虚构产品外观、包装文字、认证或功能。
- 使用产品占位符时，必须引用已确认的产品底图或产品信息。
- 生成后检查品牌包装，禁止自动出现其他品牌标识或文字。

## 内容合规

所有脚本、适配提示词、标题、正文和标签在进入发布状态前必须检查。

### 脚本交付检查清单

**结构检查：**

- [ ] 开头钩子明确。
- [ ] 分镜时间连续且总时长一致。
- [ ] 人物、服装、场景和产品状态连续。
- [ ] 镜头没有无意义重复。
- [ ] CTA 位置明确。
- [ ] 方法论与来源可以追溯。
- [ ] 标题、正文和 5 个标签齐全。

**内容检查：**

- [ ] 不虚构价格、折扣、赠品、库存或时效。
- [ ] 不使用“最好、第一、唯一、100%、保证”等无法证明的极限表达。
- [ ] 不作未经证实的医疗、治疗或治愈宣称。
- [ ] 不包含平台外引流信息。
- [ ] 不违反目标市场的宗教、文化、隐私和安全要求。
- [ ] 不混淆品牌、包装、型号和产品能力。
- [ ] 不使用来源素材中无法证明的产品事实。

### 错题本

路径：

```text
wiki/视频/共享知识库/脚本错题本/<产品名>.md
```

错误分类：

- 产品事实错误。
- 脚本结构或裂变错误。
- 模型适配和生成稳定性错误。
- 合规红线错误。
- 合成、字幕、音频和发布错误。

每条记录至少包含：编号、发现日期、错误描述、影响范围、修正措施、适用市场和关联文件。

当负责人明确说“录入错题本”时，Agent 可以直接追加记录；不得移动或覆盖原有记录。

### 裂变约束

- 先读取已批准脚本和相关知识，再确定可变轴。
- 保留原脚本骨架、事实、情绪张力、镜头语言和 CTA 位置。
- 只修改被授权的变量，例如人物画像、场景、服装、道具和表层视觉。
- 不得在裂变中发明新产品能力、促销或合规声明。
- 每条裂变必须保留 `source-script`、`methodology` 和 `knowledge-sources`。
- 同名结果使用递增编号，不覆盖已有脚本。

## 工作流

### Wiki 工作流

#### 录入产品

1. 在 `wiki/产品/产品信息/` 创建或更新产品档案。
2. 将用户确认的事实与 AI 推断明确区分。
3. 将产品图片放入 `wiki/产品/产品底图/`。
4. 更新相关索引和操作日志（如果资料库中存在这些页面）。
5. 需要主图、详情图或标题时，使用现有 Wiki 扩展目录，不改变 OPC 视频目录。

#### 摄入与查询

1. 原始资料保持只读，只追加来源索引。
2. 创建来源摘要时记录原始文件链接。
3. 查询时先读取产品信息和相关来源，再给出事实、推断和建议。
4. 有复用价值的结论进入知识页面，不把临时讨论写成正式规则。

#### 维护

定期检查：

- 产品事实是否冲突。
- Wiki-link 是否失效。
- 是否存在孤立页面。
- 是否出现旧路径或平行目录。
- 产品信息与脚本是否失去关联。
- 合规规则是否已经应用到待发布内容。

### 纯 AI 视频线路

1. **9992 视频下载与脚本解析**：把 URL 视频写入 `纯AI视频/01来源素材/<产品名>/`，解析结果写入 `纯AI视频/02参考脚本/<产品名>/`。
2. **10006 脚本创作与适配**：线路 1 做复刻或裂变；线路 2 先做产品改写再复刻或裂变；直接写入 `纯AI视频/04适配脚本/omni/<产品名>/`，不保存普通中间脚本。
3. **9995 片段产出与合成**：读取 10006 的 Omni 适配稿，写入 `纯AI视频/05AI片段/omni/<产品名>/`，把待合成任务放入 `纯AI视频/06合成工作区/`，并从同一 Agent 的片段合成入口生成 `视频/成品视频/<产品名>/`。
4. **9996 成品管理**：在同一成品目录中管理发布文案、发布记录和成品状态。
5. **旧 Agent 回退**：9993、9994、9997 暂时保留，但不作为新任务的默认入口。

`03产品脚本/<产品名>/` 保留已有历史稿和旧 Agent 回退数据；10006 的新任务不再向这里写入中间稿。

### AI 实拍混剪线路

1. **9992 混剪参考视频下载与解析**：把 URL 视频写入 `AI实拍混剪/01参考视频/<类型>/<产品名>/`，解析结果写入 `AI实拍混剪/02解析脚本/<类型>/<产品名>/`。
2. **10006 脚本创作与适配**：对钩子或 CTA 做复刻或裂变，产品资料可选；直接写入 `04适配脚本/omni/<类型>/<产品名>/<来源脚本>/`。
3. **9995 片段产出**：写入 `05AI片段/omni/<类型>/<产品名>/`。
4. **10004 音频产出**：写入 `06音频文件/<产品名>/`。
5. **10000 混剪编排**：读取 `07实拍素材/<产品名>/`，在 `08混剪工作区/<产品名>/<任务名>/` 编排和输出。
6. **旧 Agent 回退**：10003 与 9999 暂时保留；`03复刻裂变脚本` 保留历史数据，不作为 10006 新任务的中间输出。

### 自动发布流水线

- **10005** 复用现有 Agent 的底层业务能力，不复制另一套业务代码。
- 自动流水线可读取已经认可的脚本和已有成品，缺少数量时再执行裂变、适配、片段生成、合成和串行发布。
- 已有成品优先，新增生产可以按目标数量增加失败预算。
- 账号顺序、市场、语言、商品映射、发布文案和时间配置必须在任务创建时固定并记录。
- 自动流水线不得改变手动 Agent 的独立断点工作能力。

### 两个板块的交叉流程

- 新产品上线：先建立产品信息和产品底图，再进入视频生产。
- 产品信息更新：检查参考脚本以外的正式脚本、适配、片段任务和发布文案。
- 生图 Prompt 与视频 Prompt 共享同一产品事实，但按各自媒介要求编写。
- 发布数据和失败案例进入错题本，形成下一轮脚本与合规规则。

### 硬约束

- AI 可以提案和执行，但不能自行批准目录或核心规则变更。
- 修改本文件、合规规则或核心模板必须得到负责人明确授权。
- 脚本在 `compliance-status: passed` 之前不得标记为 `status: ready`。
- 高端品牌内容以产品力和使用体验为主，不使用无法证明的低价或折扣作为钩子。
- 多市场素材的共用语言由负责人确定，Agent 不得自行假设。
- AI 生图和生视频不得混淆品牌、包装、型号或竞品标识。
- 涉及发布、删除、迁移和覆盖时，必须遵守对应确认与校验流程。

## 核心写入规则

- 原始资料只读；需要修正时创建新版本或补充说明。
- 没有来源验证的内容不得写成参考脚本。
- 没有依据的经验不得写成强制规则。
- 产品事实只从产品信息和负责人确认中读取。
- 脚本发布前必须完成合规检查。
- 裂变脚本必须保留来源和方法论。
- 每个确认过的错误应进入共享错题本。
- Agent 内部上传、临时副本、中间文件、浏览器配置、数据库和日志不得进入业务资料库。
- 不得移动或删除业务文件，除非负责人明确授权并且已完成校验。
- 不得覆盖用户已有脚本、视频、音频、产品资料或本文件。

## 回答与引用格式

每个重要事实应尽量标注来源：

- `[来源: [[raw/source-file.md]]]`
- `[参见: [[wiki/related-page]]]`

回答时区分：

- **事实**：来自文件或用户确认。
- **推断**：根据现有材料推导。
- **建议**：尚未执行的方案。
- **需负责人确认**：会改变目录、规则、发布或业务数据的决定。

## 健康检查

定期检查：

1. 正式目录是否完整。
2. 是否重新出现旧目录或绝对路径。
3. 同一来源的解析、脚本、适配、片段和成品是否可追溯。
4. 是否存在未通过合规检查却进入发布状态的脚本。
5. 标题库是否与成品产品目录对应。
6. 错题本是否有未闭环记录。
7. 工作区是否混入永久素材或内部缓存。
8. Agent 配置是否仍指向 `OPC_VAULT_ROOT` 下的正式路径。

## 原则

1. **路径唯一**：同一业务资产只有一个正式存储位置。
2. **产品唯一**：所有工作流共享同一产品事实源。
3. **增量积累**：新来源和新结论整合进现有体系。
4. **交叉链接**：相关内容必须可以互相追溯。
5. **持续更新**：新信息优先更新现有页面，不堆积平行版本。
6. **用户导向**：负责人做最终决策，AI 负责整理、执行和提醒风险。
7. **手动与自动并存**：独立 Agent 保持断点能力，自动流水线复用同一底层能力。
8. **Docker 唯一运行方式**：运行环境、缓存和日志由 Docker 管理，业务资料写入挂载资料库。
