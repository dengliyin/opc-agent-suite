# AI＋实拍混剪智能体（10000）

独立完成以下成片结构：

1. AI 钩子视频（保留原音频）
2. 混剪音频＋“展示/使用”实拍素材自动混剪
3. AI CTA 视频（可选；开启时从同国家素材池自动轮换并保留原音频）

页面右侧按成品管理的卡片布局，预览当前产品与国家下的全部 AI 钩子视频，并显示模型及可用状态。

确认渲染前可勾选 `使用字幕`。字幕只包装混剪音频对应的实拍中段，AI 钩子与 AI CTA 均不加字幕。

## 目录约定

```text
AI实拍混剪/
├── 05AI片段/<模型>/混剪-钩子|混剪-CTA/<产品名>/  # 片段产出未导出工作区
├── 06音频文件/<产品名>/
├── 07实拍素材/<产品名>/展示/
├── 07实拍素材/<产品名>/使用/
├── 08混剪工作区/<产品名>/
└── 08混剪工作区/片段产出归档/<模型>/<日期>/...

成品视频/<产品名>/AI实拍混剪-*.mp4
```

## 处理原则

- 中段长度严格跟随混剪音频，不拉长或改写音频。
- CTA 不是成片必选项；未开启时，成片在中段结束。
- 每个 AI 钩子只用于一条成功成片；本次成片数量自动等于尚未使用的同国家钩子数量。
- AI 钩子与 CTA 只从 `08混剪工作区/片段产出归档` 读取；`05AI片段` 属于片段产出的未导出工作区，不进入混剪素材池。
- 来自片段产出 Agent 的已交付钩子或 CTA 会在成功成片后同步标记为“已用于混剪”；手动删除已交付钩子时同步标记“素材已清理”，片段产出端不会重新判定为未生成。
- 钩子、混剪音频及 CTA 的国家代码必须一致。
- 混剪音频同样按国家组成自动素材池，多条成片优先轮换不同音频，并按各自实际时长生成中段。
- 混剪音频不设使用次数上限。
- 开启 CTA 后从同国家 CTA 素材池自动轮换，不要求逐条选择。
- 中段前约一半使用展示素材，后约一半使用使用素材；系统根据实际展示片段时长，在最接近音频中点的完整镜头边界切换。
- 实拍素材默认使用自身完整时长，只有整条中段的最后一个镜头可为对齐混剪音频结束点而裁短。
- 每个实拍文件最多进入 5 条成功成片，同一条成片内不重复使用同一个实拍文件。
- 已成功使用过的“混剪音频＋实拍素材排列顺序”不得再次生成。
- 同一阶段优先使用历史次数较低的素材。
- 每条成片记录素材路线签名，生成多条时尽量避免重复路线。
- “去重处理”支持缩放裁切、色彩、Gamma/色温、锐化降噪、抽帧、镜像、轻微变速、边框、明显特效及编码参数变化。
- 用户可手动多选去重项目，也可选择“随机去重”，让每条成片独立随机组合若干项并自动控制强度。
- 去重只处理视频画面，不参与素材选择和排列，也不修改钩子、CTA 或混剪音频。
- 字幕包装复制自片段合成 Agent，固定使用 TikTok 卡拉 OK 逐词高亮样式；不调用远程转写 API。
- 系统优先复用混剪音频旁边的同名 `.ass` 字幕；缺失时才调用本地 Whisper，并把 `.ass`、`.srt`、`.caption.json` 保存到音频旁供后续复用。
- 字幕时间以混剪音频起点为 0 保存；成片烧录时按 AI 钩子的实际时长整体偏移，并在混剪音频结束处截断，因此不会进入钩子或 CTA。
- AI 钩子/CTA 若带技术性尾部黑屏静音，会自动识别并裁掉，不把技术填充带入成片。
- 所有成片均经过视频流、音频流和时长校验，并生成同名 `.metadata.json`。

## 启动与测试

```bash
python3 -m venv .venv
./scripts/validate_app.sh
./scripts/start_web.sh
```

首次使用卡拉 OK 字幕前，可运行：

```bash
./scripts/install_caption_runtime.sh
```

打开：`http://127.0.0.1:10000/`
